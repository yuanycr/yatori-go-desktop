# 桌面日志修复（2026-11-14）

## 改动

- 修复日志仅显示在内存、文件输出开关未生效的问题。
- 仪表盘和日志中心读取同一日志缓冲，仪表盘订阅实时日志；重启恢复最近历史，避免文件与内存重复拼接。
- 主进程统一保存 worker stdout/stderr，记录启动、退出和数据库初始化失败；超长行截断后继续读取，停止任务后尽量排空已输出内容。
- DEBUG 模式保存诊断副本；考试页面快照采用唯一文件名、大小和数量限制，写入失败明确提示。
- 日志写盘前与发送界面事件前使用相同的敏感字段脱敏处理，移除快照中的脚本和表单值。

## 保存位置与开关

用户数据根目录仍为 `%APPDATA%\yatori-go-console`。

| 内容 | 子目录 | 条件 |
| --- | --- | --- |
| 普通运行日志 | `assets\log` | `logOutFileSw: 1` |
| DEBUG 诊断日志 | `debug\logs` | 文件输出开启且 `logLevel: DEBUG` |
| 学习通考试入口页面快照 | `debug\xxt-exam` | 上述 DEBUG 条件满足，并实际执行了对应页面获取流程 |

普通/DEBUG 日志各自按 4 MiB 轮转，最多保留 12 份本修复生成的日志；快照单份最多 2 MiB，最多保留 20 份本修复生成的快照。不清理历史版本或用户自行放入的文件。

内存日志最多 1000 条且正文总量不超过 2 MiB，单条超长日志截断。截图中的固定日志面板布局未修改。

## 范围与限制

- 本次不升级 console/core、不改账号配置和任务业务规则，不创建或修改 GitHub Release，也不重建 Android APK；仅提交日志修复源码、测试和说明，EXE 不上传。
- 旧 core 的 `lg.Print` 按 INFO/DEBUG **相等**过滤，不能同时输出两种级别。本修复让其继续输出 INFO，避免开启 DEBUG 后丢失业务日志；worker 诊断、stderr、ICVE DEBUG 输出和捕获到的日志会写入诊断文件。**未声称启用旧 core 内部所有 DEBUG-only 语句**；完整分级日志支持留待核心适配处理。
- DEBUG 不是全量网络抓包，也不会在未进入对应流程时凭空生成考试 HTML。
- 敏感字段脱敏为尽力处理，诊断文件仍可能含账号名称、题目等个人信息，不应未经检查公开上传。
- 正常退出会排空捕获管道并关闭文件。异常断电或强杀整个桌面进程时，最后尚未到达主进程的日志不保证保存。
- 文件开关、诊断副本在保存设置后生效；正在运行的 worker 的诊断级别需重新启动任务生效。

## 验证方式

在临时目录、内存数据库和模拟输出上验证，不使用真实账号任务：

```powershell
go test ./... -count=1
go vet ./...
go test -race ./service -run 'Test(Log|Debug|Dashboard|WorkerDrains|TaskManager)' -count=1
node --test frontend/tests/dashboard.test.cjs
npm --prefix frontend run build
```

新增测试覆盖保存、重启、开关、轮转、旧文件保留、写入失败恢复、5 账号并发写入、超长行、stdout/stderr 尾部排空、快照唯一命名和脱敏、仪表盘实时数据以及异步响应顺序。最新 EXE 单独命名为日志修复测试版，保留已发布的 v0.4.2 EXE。
